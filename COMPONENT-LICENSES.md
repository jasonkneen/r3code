# Component license inventory

Which license applies to which part of this repository, and why.

Two categories only:

- **AGPL-3.0-only** — original R3 Code work, rights held by Jason Kneen. Full
  text in `LICENSE`.
- **T3 Code MIT (retained)** — material derived from T3 Code in content or
  format. Not relicensed; see `LICENSES/T3-Code-MIT.txt` and the upstream
  project at <https://github.com/pingdotgg/t3code>.

Anything not listed below as T3-derived is AGPL-3.0-only. Third-party
dependencies and vendored code keep their own licenses (see "Third-party
components" in `LICENSING.md`), and are not listed here.

## T3 Code-derived — license retained, not AGPL

These files take their content or format from upstream T3 Code. Each was
produced by reading upstream source, by copying upstream copy/labels, or by
matching an upstream contract. They remain MIT under T3 Tools Inc.'s notice.

### Generated from upstream source (content and structure)

Generated by reading T3 Code's settings surface, theme palettes, contracts or
assets. Headers in each file name the upstream path they came from.

- `t3ui/settingsPanels.ts` — generated from upstream
  `components/settings/SettingsPanels.tsx`, `settingsSearch.ts` and related
  settings sources; carries upstream row titles and descriptions verbatim.
- `t3ui/settingsNav.ts` — generated from upstream
  `components/settings/settingsSearch.ts`.
- `t3ui/pages/Settings.tsx` — populated from the generated nav/panel data, so
  its labels are upstream's shipped labels.
- `t3ui/themePaletteData.ts` — generated from upstream
  `packages/shared/src/themePalettes.ts`.
- `t3ui/themePreviews.ts` — generated from the same upstream palette source.
- `t3ui/backend/rpcResultSchema.ts` and `t3ui/backend/rpcResultSchemas.json` —
  success schemas generated from upstream `packages/contracts`; the decode
  behaviour mirrors upstream's `RpcClient`.
- `t3ui/backend/rpcConcurrency.ts` — mirrors upstream client-runtime
  `state/runtime.ts` command-scheduler semantics and keying.
- `t3ui/desktop/snapShotSounds.ts` — base64 of upstream
  `apps/web/src/assets/snap-shot-whoosh.mp3` and `snap-shot-click.mp3`.

### Upstream assets (icons and glyphs)

Extracted from the upstream app or its icon set; names and shapes are upstream's.

- `t3ui/components/files/icons/` — file-type icons, including the `t3/` branded
  provider marks (`agents.svg`, `csharp.svg`, `dart.svg`, `diff.svg`,
  `elixir.svg`, and the rest of the 23 files in that directory).
- `t3ui/components/files/viewers/` — the bundled document-viewer pages and their
  SVG parts/assets, generated by `third_party/doc-viewer` from doc-viewer
  sources.
- `t3ui/theme.json` — theme token names, CSS variable names and the light/dark
  value structure follow upstream's theme contract. Note: the colour values
  themselves are R3's; the token vocabulary and JSON schema are upstream's, so
  the file is held as T3-derived to be safe. If the colour data is confirmed
  R3-original, this file may move to AGPL with the schema documented instead.

## AGPL-3.0-only — everything else

Including, but not limited to:

- `t3ui/**` other than the paths listed above (components, pages, shell, store,
  commands, desktop integration, environments, backend runtime, tests);
- `server-rs/src/**`, `server-rs/tests/**`, `server-rs/migrations/**` — the Rust
  server and its storage layer;
- `tools/**` — build, packaging, signing, release and runtime staging;
- `website/`, `website-backend/` (held back from publication);
- root and `docs/` documentation written for R3 Code.

## Notes for contributors

- New files you write for R3 Code are AGPL-3.0-only unless they copy or
  regenerate upstream content.
- If you copy upstream text, labels, schemas or assets into a file, add it to
  the T3-derived list above in the same change. A file that is part upstream
  content is T3-derived for licensing purposes even if you rewrote most of it.
- Regenerating one of the listed generated files does not change its license.
